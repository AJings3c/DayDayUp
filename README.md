# DayDayUp

DayDayUp 是一个面向个人学习成长的 macOS 原生学习执行监督工具。

它的目标不是替你制定学习路线，也不是自动拆解任务。学习路线、阶段目标、任务内容都由使用者自己决定。DayDayUp 只负责一件事：把你已经写下来的学习任务变成可执行、可倒计时、可提醒、可追踪、可复盘的日常系统。

## 项目结构

- `DayDayUp/App`：应用入口与全局启动配置。
- `DayDayUp/Models`：SwiftData 模型、状态规则与评分计算。
- `DayDayUp/Services`：提醒调度、通知 request id、JSON 备份导出和导入合并。
- `DayDayUp/Design`：颜色、玻璃效果、小松鼠 IP 状态图加载与通用组件。
- `DayDayUp/Views`：启动倒计时、今日执行、任务管理、数据评分、学习历程和菜单栏视图。
- `DayDayUp/Assets.xcassets`：运行时图片资源、6 种小松鼠状态图和 macOS Dock 图标。
- `DayDayUpTests`：任务状态、评分、日历、里程碑和提醒规则测试。
- `docs`：产品定位、交互设计规范、Logo 与小松鼠 IP 简报。
- `design`：Stitch 视觉参考和生成图源，不参与 App 运行时资源加载。

## 产品定位

DayDayUp 服务于一个正在从 AI 应用开发小白成长为大模型应用开发者或智能体开发工程师的人。

使用者会参考 GitHub 学习路线、开源项目、课程、论文、文档和实战项目，自己制定学习计划，并把具体任务录入应用。应用不干预任务如何规划，只监控任务是否按时推进，帮助使用者减少拖延、保持节奏、看见进度。

一句话定位：

> 一个安静、克制、原生的 macOS 学习执行监督台。

## 核心问题

DayDayUp 主要解决这些问题：

- 学习任务写下来了，但缺少持续提醒和时间压力。
- 长期目标很清楚，但每天不知道应该先做哪一项。
- 学习进度分散在笔记、GitHub、浏览器书签和脑子里。
- 容易拖延，等到截止时间接近才开始推进。
- 学了很多，但缺少可回看的数据和复盘依据。

## 设计原则

1. 用户自己规划任务，应用只监督执行。
2. 打开应用后，下一步要做什么必须一眼可见。
3. 倒计时提供压力，但界面不能制造焦虑。
4. 数据看板要具体、克制、可行动，不做花哨展示。
5. 优先遵循 macOS 原生交互和视觉习惯。

## 核心功能

### 任务录入

用户手动创建学习任务，每个任务可以包含：

- 任务名称
- 任务内容
- 所属学习方向，比如 AI Agent、RAG、vibe coding、大模型应用开发
- 截止时间
- 预计学习时长
- 当前完成度
- 完成标准
- 制定日期
- 完成日期
- 逾期状态
- 卡住原因
- 学习资料链接
- 备注

### 任务倒计时

每个任务都有清晰的剩余时间提示：

- 距离截止时间还有多久
- 是否已经逾期
- 当前进度是否落后
- 今天建议投入多少时间

### 今日执行

今日视图只展示最关键的信息：

- 当前最应该执行的任务
- 今日待完成任务
- 任务倒计时
- 今日已学习时间
- 今日完成情况

### 专注计时

用户选择一个任务后进入专注模式：

- 开始、暂停、结束一次学习时段
- 记录本次学习时长
- 快速写下学习备注
- 完成后更新任务进度

### 数据看板

数据看板用于复盘学习节奏，而不是制造复杂报表：

- 今日学习时长
- 本周学习时长
- 连续打卡天数
- 任务完成率
- 准时完成率
- 提前完成率
- 逾期任务数量
- 延迟完成率
- 任务闭环率
- 补完成率
- 各学习方向投入时间
- 任务完成趋势
- 任务日历

### 学习执行力雷达图

应用应提供一个核心图表，用来表达任务执行质量。

推荐使用“学习执行力雷达图”，展示这些维度：

- 任务完成度
- 准时完成率
- 提前完成率
- 延迟控制率
- 专注稳定度
- 复盘完整度

辅助诊断指标：

- 任务闭环率
- 补完成率
- 未闭环任务数
- 平均延期时长

雷达图旁边显示一个 100 分制的执行力评分，让用户快速知道当前学习节奏是否健康。

评分建议：

- 任务完成度：30 分。
- 准时完成率：25 分。
- 提前完成率：10 分。
- 延迟控制率：15 分。
- 专注稳定度：15 分。
- 复盘完整度：5 分。

评分等级：

- 90 到 100 分：节奏优秀。
- 75 到 89 分：节奏稳定。
- 60 到 74 分：需要调整。
- 0 到 59 分：执行风险较高。

这个评分不是为了制造焦虑，而是帮助用户发现拖延、延期和学习节奏不稳定的问题。

### 任务日历

任务日历用于表达每天的执行状态：

- 按时或提前完成任务的日期显示为绿色。
- 没有任务完成的日期显示为普通默认颜色。
- 如果任务逾期未完成，那么这个任务的截止日期显示为红色。
- 如果逾期任务后来补上，那么原本红色的截止日期调整为紫色。
- 如果同一天同时存在多种状态，优先级为红色、紫色、绿色、普通默认色。

### 学习历程

学习历程以每个任务为单位归档，记录任务是否真正闭环。

每个任务的学习历程应包含：

- 哪一天制定计划。
- 哪一天开始执行。
- 哪一天完成任务。
- 是否按时完成。
- 是否逾期未完成。
- 是否逾期后补完成。
- 当前完成度。
- 延期时长。
- 卡住原因。
- 补救记录。
- 复盘备注。

如果任务没有完成，就不能算作闭环。用户点开任务时，需要能看到任务卡在了哪一步，以及为什么没有及时完成。

任务完成后的核心反馈文案是：

> 任务完成啦，开始干饭！

### 学习里程碑

DayDayUp 可以记录克制的学习里程碑，比如首次完成任务、首次按时闭环、首次补完成、连续专注、连续复盘和累计学习时长节点。

里程碑是学习档案的一部分，用来帮助用户看见长期积累，不做积分、等级、排行榜或持续打扰式奖励。

## 品牌与标志

DayDayUp 的产品标志可以是一只生动活泼的小松鼠。

小松鼠象征持续积累、敏捷行动、长期准备和自我驱动。它像学习者一样，一点点储存自己的“松果”：知识、代码、项目经验、复盘记录和解决问题的能力。

这个角色应该聪明、有精神、有行动感，但不能过度幼稚。它可以出现在产品标志、空状态、完成反馈和轻量提醒中，但不应该打断用户学习。

## macOS 原生方向

DayDayUp 应优先作为 macOS 原生应用设计和实现。

推荐方向：

- 使用 SwiftUI 构建界面。
- 使用 SwiftData 存储任务、学习记录和设置。
- 使用 UserNotifications 做提醒。
- 使用 MenuBarExtra 在菜单栏显示当前任务倒计时。
- 使用 NavigationSplitView 组织路线、任务列表和详情。
- 适配 macOS Liquid Glass 视觉语言，但玻璃效果只用于层级和聚焦，不作为装饰堆叠。
- App 图标使用 macOS 圆角图标结构，运行时 Dock 图标跟随系统浅色和深色外观切换。

## 非目标

DayDayUp 暂时不做这些事情：

- 自动生成学习路线。
- 自动拆解 GitHub Roadmap。
- 社交打卡、排行榜、群组监督。
- 复杂项目管理，比如甘特图、多人协作、权限管理。
- 过度游戏化，比如大量徽章、积分、等级和动画奖励。

## 最小可行版本范围

第一版建议先做五个核心页面：

1. 启动倒计时
2. 今日执行
3. 任务管理
4. 数据评分
5. 学习历程

数据看板可以先做轻量版本，只展示今日、本周、连续天数、完成率、提前完成率、延迟完成率、补完成率、任务闭环率和执行力评分。

## 产品气质

DayDayUp 应该安静、专注、克制。

它不是一个让人兴奋五分钟的新工具，而是一个可以每天打开、每天使用、每天帮助自己往前走一点的学习系统。
