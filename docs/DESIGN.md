# Design System: DayDayUp

## Overview

**Creative North Star: "松果仓库里的学习指挥台"**

DayDayUp 的设计语言来自一个具体画面：一只清醒、灵活的小松鼠，把每天收集到的松果整齐放进仓库。这里的松果不是装饰，而是知识、代码、项目经验、复盘记录和解决问题的能力。界面要像一个安静的学习指挥台，打开后立刻知道下一步做什么，不需要解释，不需要热闹，不需要情绪刺激。

整体气质必须是 macOS 原生生产力工具：克制、清晰、轻盈、响应迅速。Liquid Glass 可以用于侧边栏、工具栏、浮层和选中态，但只能帮助层级表达，不能堆叠成玻璃卡片秀。产品的可爱感来自小松鼠的精神和少量反馈，不来自幼稚插画、夸张动效或大量吉祥物台词。

设计必须直接拒绝普通习惯打卡应用、复杂项目管理软件、营销落地页式界面、普通网页看板和过度 AI 风格化界面。用户来这里是为了执行学习任务，不是欣赏一个会分散注意力的视觉系统。

**关键特征：**

- 安静专注：主界面低噪音，下一任务和时间压力最突出。
- 原生可信：遵循 macOS 的侧边栏、工具栏、列表、详情和菜单栏习惯。
- 数据克制：图表用于复盘执行质量，不用于炫耀指标。
- 灵活有生命力：小松鼠代表持续积累、敏捷行动、长期准备和自我驱动。
- 清晰可执行：每个页面都要指向行动，尤其是开始学习、更新进度、完成复盘。

## Colors

色彩策略是克制型：纯白和冷静浅灰构成主工作区，感知蓝作为主操作色，松鼠铜作为品牌温度和少量强调色。任何单屏中，品牌强调色总面积不应超过 10%。

### Primary

- **感知蓝**：主操作、当前选中、关键链接、学习执行力主图形。它表达冷静、清晰和系统化监督。
- **深夜蓝**：用于 100 分评分、重要数字和高权重状态。它必须少量出现，用来建立可信度。

### Secondary

- **松鼠铜**：用于产品标志、小松鼠角色、完成反馈、轻量提醒和少量品牌强调。它不能变成大面积橙色主题。

### Tertiary

- **松针绿**：用于准时完成、节奏优秀、已完成等正向状态。
- **琥珀警示**：用于接近截止时间、进度落后但仍可补救的状态。
- **克制红**：只用于逾期、执行风险较高和需要立即处理的任务。
- **补完成紫**：用于逾期后补完成的任务。它表达“曾经延期，但已经补上”，不能和红色逾期未完成混淆。

### Neutral

- **纯白工作台**：主背景。不要使用奶油色、纸张色或泛黄暖底。
- **冷雾面板**：任务列表、详情区和看板模块的低对比背景。
- **浅蓝选中面**：选中任务、当前路线、当前图表筛选项。
- **墨色正文**：主要文本和关键数据。
- **石板灰说明**：次级说明、时间戳、辅助标签。不能浅到影响阅读。
- **雾线边界**：分隔线、输入框边界、图表辅助线。

### 命名规则

**安静表面规则。** 主背景必须接近纯白，品牌感由感知蓝和松鼠铜承担，不能靠暖色背景制造“温柔感”。

**系统外观规则。** 颜色 token 必须支持 macOS 浅色和深色外观。浅色模式保持纯白工作台和冷雾层级；深色模式使用低饱和深色工作台、清晰文字和克制状态色，不能简单反相，也不能退回网页式深色看板。

**松鼠强调规则。** 松鼠铜只用于品牌和少量奖励反馈，不能覆盖按钮体系、数据图主色或大面积背景。

**数据优先规则。** 图表颜色必须服务状态识别：按时完成、逾期未完成、逾期后补完成、普通日期要能一眼区分，并且不能只依赖颜色。

## Typography

**展示字体：** SF Pro Display，使用系统回退字体  
**正文字体：** SF Pro Text，使用系统回退字体  
**标签和数字字体：** SF Mono，只用于计时器、评分、倒计时和对齐数字数据

**字体性格：** 字体系统应该完全贴近 macOS 原生体验。不要使用装饰性标题字体，不要用手写体表达小松鼠，不要为了“AI 感”引入科技感过强的字体。

### Hierarchy

- **Display**：粗体，32px，1.15 行高。只用于页面主标题、执行力评分主数字附近的大标题。
- **Headline**：半粗体，24px，1.2 行高。用于今日看板区块标题和数据看板标题。
- **Title**：半粗体，17px，1.35 行高。用于任务名称、详情标题、列表分组。
- **Body**：常规，14px，1.55 行高。用于任务内容、完成标准、复盘备注。长文本行宽控制在 65 到 75 个字符以内。
- **Label**：中等字重，12px，1.25 行高。用于状态、字段名、筛选项、图例。不要全大写。
- **Metric**：SF Mono，28px，1.1 行高。用于倒计时、执行力分数、学习时长和完成率。

### 命名规则

**原生字体规则。** 所有界面文字都使用 Apple 系统字体体系，产品标志文字可以有轻微品牌处理，但不能破坏 macOS 原生感。

**数字稳定规则。** 倒计时和评分必须稳定、等宽、易扫读。数字变化不能跳动布局。

## Elevation

DayDayUp 采用色调分层加 macOS 材质的混合策略。默认状态下界面应该近似扁平，靠背景层级、细边界和选中态表达结构。阴影只能用于浮层、菜单、弹出详情、悬浮操作和窗口层级，不用于装饰性卡片堆叠。

### 阴影词汇

- **Panel Lift**：轻微阴影，用于浮层和菜单。阴影应该柔和，模糊半径小，不制造网页卡片感。
- **Focus Ring**：使用系统蓝或感知蓝的清晰描边，用于键盘焦点和输入状态。
- **Glass Layer**：用于侧边栏、工具栏和菜单栏弹出视图，透明度必须克制，文字可读性优先。

### 命名规则

**默认扁平规则。** 静态内容默认不投影。只有浮层、悬停、焦点和拖拽状态允许出现深度变化。

**玻璃必须有职责规则。** Liquid Glass 只用于层级、聚焦和系统一致性。没有信息结构作用的玻璃效果禁止使用。

## Components

### 按钮

- **形状：** 轻微圆角，使用 8px。不要使用夸张胶囊形主按钮，除非是小尺寸状态标签。
- **主按钮：** 感知蓝背景，白色文字，用于“开始学习”“保存任务”“完成复盘”等明确动作。
- **悬停和焦点：** 悬停时轻微加深或抬升，150 到 200ms。键盘焦点必须有清晰描边。
- **次级和幽灵按钮：** 次级按钮使用冷雾面板或透明背景，文字为墨色正文。危险操作使用克制红，不要默认红底。

### 标签

- **样式：** 使用 999px 胶囊形，只用于状态和筛选，例如“今日”“逾期”“提前完成”“学习方向”。
- **状态：** 选中态可以使用浅蓝选中面，文字保持墨色正文。高风险状态使用琥珀或克制红，但要搭配文字标签。

### 卡片和容器

- **圆角：** 普通容器 8px，大型图表容器 12px。
- **背景：** 主内容优先使用纯白，分区使用冷雾面板。
- **阴影策略：** 默认无阴影。浮层才允许阴影。
- **边界：** 使用雾线边界。不要使用彩色侧边条。
- **内部间距：** 紧凑工具区 12px，普通模块 16px，数据看板 24px。

### 输入框和字段

- **样式：** 原生 macOS 表单感，浅背景、细边界、8px 圆角。
- **焦点：** 使用感知蓝描边或系统焦点环。
- **错误和禁用：** 错误状态用克制红加文字说明；禁用状态降低对比但仍可读。

### 导航

- **样式：** 使用三栏或双栏 macOS 原生结构。左侧是学习方向或筛选，中央是任务列表，右侧是任务详情或数据面板。
- **当前状态：** 当前路线和当前任务使用浅蓝选中面，不用重色块。
- **工具栏：** 工具栏承载新增任务、筛选、搜索、开始专注和菜单栏入口。

### 标志性组件：学习执行力雷达图

雷达图是数据看板核心，用来表达任务完成度、准时完成率、提前完成率、延迟控制率、专注稳定度和复盘完整度。主图使用感知蓝，正向状态可以少量使用松针绿，风险提示使用琥珀或克制红，逾期后补完成使用补完成紫。雷达图旁边显示 100 分执行力评分，分数必须有文字解释，不能只给数字。任务闭环率和补完成率作为辅助诊断指标展示，不要硬塞进雷达图导致信息过载。

### 标志性组件：任务日历

任务日历用于表达每天的任务执行结果。按时或提前完成的日期使用绿色状态；没有完成记录、也没有逾期截止任务的日期使用默认状态；逾期未完成任务的截止日期使用红色状态；逾期后补完成任务的原截止日期使用紫色状态。状态优先级为红色、紫色、绿色、默认。日历必须带图例、文字或符号说明，不能只依赖颜色。

### 标志性组件：学习历程

学习历程以任务为单位展示任务是否闭环。每个任务应有时间轴：制定计划、开始执行、进度更新、截止时间、按时完成或逾期、补完成、复盘。闭环任务使用绿色或紫色状态，未闭环任务使用红色或默认进行中状态。用户必须能从这个页面看出任务卡住的位置。

### 标志性组件：学习里程碑

学习里程碑用于记录长期学习过程中的关键节点，不是积分系统、等级系统或排行榜。首批里程碑包括首次完成任务、首次按时闭环、首次提前完成、首次逾期后补完成、连续专注、连续复盘、本周无逾期、单月闭环率达标和累计学习时长节点。

里程碑必须作为学习档案长期保存。数据评分页可以展示已解锁数量、最近解锁和下一批可解锁目标；学习历程详情可以展示与当前任务相关的里程碑。启动倒计时和今日执行页只允许出现一次性轻量浮层，不允许常驻打扰。

### 动效原则

动效只服务状态反馈。任务完成时，小松鼠可以轻微缩放，配合“任务完成啦，开始干饭！”；逾期未完成时，可以有一次短促提醒；逾期后补完成时，红色状态过渡为紫色；日历、雷达图和评分数值可以使用 150 到 220ms 的原生感过渡。

禁止满屏庆祝、循环动画、积分爆炸、夸张粒子和声音奖励。开启 macOS Reduce Motion 后，所有位移、缩放和抖动都必须关闭，改为淡入或即时状态切换。

### 标志性组件：小松鼠产品标志

小松鼠应该生动、聪明、有行动感。它可以抱着松果、站在学习任务旁、或像正在整理知识仓库。形象需要适合 macOS 图标：轮廓清晰，表情轻快，细节不过度复杂，缩小到 32px 仍能识别。不要做成幼儿风贴纸，不要做夸张 3D 吉祥物，不要使用过度发光或 AI 赛博风。

App 图标必须使用 macOS 原生图标结构：透明画布、圆角底座、柔和投影、边缘高光和清晰主体。静态 bundle 图标使用标准 `AppIcon.icns`；运行时 Dock 图标根据系统浅色/深色外观切换浅色与深色版本。菜单栏入口优先使用系统符号，保持 macOS 菜单栏的单色、克制和可读性。

### 页面和交互规范

DayDayUp 只有一份设计文档，页面视觉、交互逻辑、状态颜色和跳转规则都写在这里。五个主要页面是：启动倒计时页、今日执行页、任务管理页、数据评分页、学习历程页。专注计时不作为独立主页面，而是今日执行页里的核心执行状态。

#### 全局交互原则

- 打开应用后，第一眼必须看到最近一次任务的截止时间。
- 所有页面都要能回到“当前最应该执行的任务”。
- 小松鼠只负责表达任务状态和轻量情绪，不打断用户操作。
- 倒计时提供压力，但文案不能责备用户。
- 数据评分用于复盘，不用于制造焦虑。
- 页面跳转优先使用 macOS 原生结构：侧边栏、工具栏、列表、详情、弹出层。
- 所有模块必须统一任务状态颜色：绿色表示按时或提前完成，红色表示逾期未完成，紫色表示逾期后补完成，默认色表示普通状态。

#### 全局状态颜色

- **绿色：** 任务按时完成或提前完成。
- **红色：** 任务已经逾期，且当前仍未完成。
- **紫色：** 任务曾经逾期，但后来已经补完成。
- **默认色：** 任务未完成但未逾期，或当天没有完成和逾期记录。
- **琥珀色：** 任务接近截止时间或进度落后，但还没有逾期。

颜色优先级：红色最高，紫色次之，绿色再次之，默认色最低。任务日历、任务列表、状态标签、评分解释、学习历程和菜单栏都必须遵守同一套颜色规则。

#### 页面一：启动倒计时页

启动倒计时页是首次进入应用时看到的页面。它展示最近一次任务的截止时间，并根据任务完成状态切换小松鼠情绪。“最近一次任务”指当前未完成任务中截止时间最近的任务。如果没有未完成任务，则展示最近完成的一项任务和下一步建议。

```text
+--------------------------------------------------------------+
| DayDayUp                                             [设置]   |
+--------------------------------------------------------------+
|                                                              |
|                    最近任务倒计时                             |
|                                                              |
|                 +----------------------+                     |
|                 |  任务名称              |                     |
|                 |  截止时间: YYYY-MM-DD   |                     |
|                 +----------------------+                     |
|                                                              |
|                       02 天 05:18:42                         |
|                                                              |
|            +----------------------------------+              |
|            |          小松鼠状态区             |              |
|            |   未完成：皱眉、跺脚、抱空篮子     |              |
|            |   已完成：抱着松果，笑脸盈盈       |              |
|            +----------------------------------+              |
|                                                              |
|              状态文案：根据完成状态展示                         |
|                                                              |
|          [开始今日执行]   [查看任务详情]   [新建任务]          |
|                                                              |
+--------------------------------------------------------------+
```

核心元素：应用名称、最近任务名称、最近任务截止时间、大号倒计时、小松鼠状态区、状态文案、开始今日执行、查看任务详情、新建任务、设置入口。

小松鼠状态：

- **未完成，未逾期：** 小松鼠皱眉、看倒计时、抱着空篮子。文案可以是“还差一颗松果，先收好再开饭。”主按钮是“开始今日执行”。
- **未完成，已逾期：** 小松鼠闹脾气、跺脚、尾巴炸开、空篮子倒在旁边。文案可以是“这颗松果拖太久啦，先补上再开饭。”主按钮是“立刻补任务”。
- **已完成：** 小松鼠抱着松果，笑脸盈盈。主文案固定为“任务完成啦，开始干饭！”主按钮是“查看今日任务”。
- **逾期后补完成：** 小松鼠抱着松果，旁边带紫色“补完成”状态标签。文案可以是“任务补上啦，记得看看卡在哪里。”主按钮是“查看学习历程”。
- **没有任何任务：** 小松鼠抱着空篮子，期待地看向用户。文案是“篮子还空着，先放进第一颗松果。”主按钮是“新建任务”。

交互规则：

- 应用启动后默认进入本页。
- 倒计时每秒更新，但数字区域必须固定宽度，避免布局跳动。
- 点击任务卡片，进入任务管理页并选中该任务。
- 点击开始今日执行，进入今日执行页，并自动选中最近任务。
- 点击查看任务详情，进入任务管理页右侧详情。
- 点击新建任务，进入任务管理页并打开新建任务表单。
- 如果任务在本页被标记完成，小松鼠状态立刻从“闹脾气”切换为“抱松果笑脸”，文案显示“任务完成啦，开始干饭！”
- 如果任务逾期后补完成，启动页不再显示红色逾期状态，而是显示紫色“补完成”状态，并提供查看学习历程入口。

- 左侧今日任务按时间压力排序：逾期任务、今日截止任务、最近截止任务、普通任务。
- 今日任务列表必须显示状态颜色：红色为逾期未完成，紫色为逾期后补完成，绿色为按时或提前完成，默认色为未逾期进行中。
- 点击左侧任务，右侧切换当前执行任务。
- 点击开始专注后，计时器开始，按钮变为暂停和完成本次学习。

- 如果进度达到 100%，系统询问是否标记任务完成。

#### 页面三：任务管理页

任务管理页用于手动录入、查看、编辑和完成任务。应用不自动拆任务，只承接用户已经规划好的学习任务。

交互规则：

- 点击学习方向，任务列表按方向过滤。
- 搜索实时过滤任务名称、内容、备注和链接。
- 筛选支持：全部、今日、逾期未完成、逾期后补完成、未完成、已完成、提前完成。
- 点击任务列表项，右侧详情区切换为该任务。
- 新建任务时，右侧详情区进入空表单状态。
- 保存任务后，列表立即插入或更新。
- 修改截止时间后，启动倒计时页的最近任务需要重新计算。
- 点击开始执行，跳转今日执行页并选中该任务。
- 点击完成任务，弹出确认层，要求填写完成说明或复盘备注。
- 如果逾期任务在任务管理页被标记完成，任务状态从红色变为紫色，并同步更新任务日历、数据评分和学习历程。
- 点击任务状态标签，可以跳转学习历程页查看该任务闭环记录。

任务状态规则：

- 未开始：完成度为 0%，没有学习记录。
- 进行中：完成度大于 0% 且小于 100%。
- 已完成：完成度为 100%，并且用户确认完成。
- 提前完成：完成时间早于截止时间。
- 准时完成：完成时间在截止时间当天或之前。
- 延迟完成：完成时间晚于截止时间。
- 逾期未完成：当前时间晚于截止时间，且任务未完成。
- 逾期后补完成：任务曾经超过截止时间，后来被用户标记完成。
- 已闭环：任务已完成，并且达到用户设定的完成标准。
- 未闭环：任务未完成，或虽然有进度但没有达到完成标准。

- 时间范围支持：今日、本周、本月、全部。

- 点击雷达图维度，右侧或下方展示该维度的任务明细。
- 点击日历日期，展示当天完成任务、当天截止任务和当天逾期任务。
- 点击风险任务，跳转学习历程页并选中对应任务。
- 点击补完成率，进入学习历程页并筛选“逾期后补完成”任务。
- 点击任务闭环率，进入学习历程页并筛选“未闭环”任务。
- 评分变化后，不使用夸张庆祝动画，只显示轻量状态反馈。

任务日历规则：

- 按时或提前完成任务的日期显示为绿色。
- 没有任务完成、没有逾期截止任务的日期显示为普通默认颜色。
- 如果某个任务逾期未完成，则该任务的截止日期显示为红色。
- 如果逾期任务后来被补完成，则原本红色的截止日期调整为紫色。
- 红色优先级高于紫色，紫色优先级高于绿色。
- 如果任务逾期后补完成，实际完成日期可以显示绿色完成点，但该任务原截止日期必须显示紫色，表示这项任务不是按时闭环。
- 日历不能只依赖颜色表达状态，必须配合图例、符号或文字说明。
- 点击绿色日期，展示当天完成了哪些任务。
- 点击红色日期，展示哪些任务在这一天截止但没有按时完成。
- 点击紫色日期，展示哪些任务曾在这一天截止，并且后来补完成。

评分展示规则：

- 90 到 100 分：节奏优秀。
- 75 到 89 分：节奏稳定。
- 60 到 74 分：需要调整。
- 0 到 59 分：执行风险较高。

评分文案必须说明原因，例如“准时完成率不错，但复盘记录偏少”“延期任务偏多，建议先处理最近截止任务”“提前完成率提升，本周节奏更稳定”。

#### 页面五：学习历程页

学习历程页用于按任务归档完整执行过程。它回答三个问题：这个任务什么时候制定的，这个任务是否按时闭环，如果没有闭环，卡在了哪里。

核心元素：任务归档列表、状态筛选、任务闭环状态、当前完成度、制定日期、开始执行日期、截止时间、完成日期、延期时长、卡住原因、补救记录、复盘备注、时间线、记录卡住原因、补完成、查看任务详情。

闭环判断规则：

- 已闭环：任务已经达到完成标准，并由用户确认完成。
- 未闭环：任务没有完成，或完成度没有达到 100%。
- 按时闭环：任务在截止时间前或截止时间当天完成。
- 提前闭环：任务早于截止时间完成。
- 逾期未闭环：当前时间超过截止时间，任务仍未完成。
- 逾期后补闭环：任务曾经逾期，但后来被用户补完成。

参考性指标：

- 完成度。
- 是否闭环。
- 是否按时完成。
- 是否逾期。
- 是否逾期后补完成。
- 延期时长。
- 制定计划到开始执行的间隔。
- 开始执行到完成的间隔。
- 专注学习时长。
- 复盘完整度。
- 卡住原因。
- 补救记录。

如果任务没有完成，就不能显示为闭环。未闭环任务必须突出“卡住位置”，例如未开始、进度停滞、逾期未补、缺少复盘。

交互规则：

- 默认按最近更新时间排序。
- 点击任务归档列表项，右侧展示该任务完整历程。
- 点击“只看未闭环”，列表只展示未完成、逾期未完成和缺少完成确认的任务。
- 点击“逾期后补完成”筛选，只展示紫色状态任务。
- 点击“记录卡住原因”，在当前任务下追加一条阻塞记录。
- 点击“补完成”，要求用户确认完成度、完成日期、补救说明和复盘备注。
- 补完成保存后，该任务状态从红色变为紫色，任务日历中原截止日期从红色调整为紫色。
- 点击“查看任务详情”，跳转任务管理页并选中该任务。
- 从数据评分页点击补完成率、任务闭环率、日历紫色日期或风险任务时，进入本页并自动应用对应筛选。

#### 文案语气

整体文案要像小松鼠在认真提醒用户收松果：轻快、具体、有一点生活感，但不幼稚、不责备。任务完成后的主文案固定为：“任务完成啦，开始干饭！”

推荐文案：

- “任务完成啦，开始干饭！”
- “这颗松果收好了，继续下一颗。”
- “最近的任务还没完成，先把它拿下。”
- “这颗松果拖太久啦，先补上再开饭。”
- “今天的篮子还空着，先开始 25 分钟。”
- “本周节奏稳定，但复盘记录偏少。”

禁止文案：

- “你又拖延了。”
- “你失败了。”
- “赶快学习！”
- “再不学就完了。”
- “主人，我来监督你啦！”

- 如果任务完成，菜单栏面板显示小松鼠抱松果状态和“任务完成啦，开始干饭！”
- 如果任务逾期未完成，菜单栏面板显示红色状态和小松鼠闹脾气状态，但不使用强打扰动画。
- 如果任务逾期后补完成，菜单栏面板显示紫色状态和小松鼠抱松果状态。

## Do's and Don'ts

### Do:

- **Do** 让“当前最应该执行的任务”成为今日看板的视觉中心。
- **Do** 使用学习执行力雷达图表达完成度、准时完成率、提前完成率、延迟控制率、专注稳定度和复盘完整度。
- **Do** 使用任务日历表达每天的完成、普通、逾期未完成和逾期后补完成状态。
- **Do** 使用学习历程记录每个任务从制定到完成或卡住的完整闭环。
- **Do** 把成就表达为学习里程碑，作为复盘档案的一部分。
- **Do** 在执行力评分旁边解释分数原因，例如“延期任务偏多”或“本周专注稳定”。
- **Do** 保持 macOS 原生结构，优先使用侧边栏、列表、详情、工具栏和菜单栏入口。
- **Do** 让小松鼠承担品牌温度，但只在产品标志、空状态、完成反馈和轻量提醒中出现。
- **Do** 使用文字、形状和数值辅助图表状态，不能只靠颜色区分完成、延期和风险。

### Don't:

- **Don't** 做成充满徽章、积分、排行榜和社交压力的习惯打卡应用。
- **Don't** 做成复杂的项目管理软件，比如带有大量字段、视图和协作功能的任务系统。
- **Don't** 做成伪装成应用的营销落地页。
- **Don't** 做成忽略 macOS 平台习惯的普通网页看板。
- **Don't** 使用过度 AI 风格化界面，比如大量渐变、发光面板和装饰动画。
- **Don't** 做成积分、等级、排行榜、道具商店或持续弹窗式游戏化系统。
- **Don't** 使用暖奶油背景、深蓝网页仪表盘、紫色 AI 渐变或玻璃卡片堆叠作为默认视觉套路。
- **Don't** 让小松鼠变成喧宾夺主的动画吉祥物。它代表持续积累和敏捷行动，不负责卖萌打扰学习。
- **Don't** 用大面积松鼠铜覆盖界面。它是品牌强调，不是主题底色。
