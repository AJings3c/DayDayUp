# 产品

## Register

product

## 用户

主要用户是这个项目的创建者：一个正在学习 AI Agent、vibe coding、RAG 和大模型应用开发的人，目标是从小白成长为专业的大模型应用开发者或智能体开发工程师。

用户会参考 GitHub 学习路线、开源项目、课程、论文、文档和实战项目，自己制定学习计划，并把具体任务手动录入应用。应用不负责自动拆解路线，也不替用户规划学习任务，只负责监控这些任务的时间、进度、提醒和复盘。

## 产品目标

DayDayUp 是一个安静的个人学习执行监督台，用于支持长期 AI 工程学习。

它帮助用户：

- 追踪手动录入的学习任务，包括任务内容、截止时间和完成标准。
- 通过任务倒计时和提醒，让时间压力保持可见。
- 记录学习进度，减少维护复杂表格或分散笔记的成本。
- 记录每个任务从制定、执行、逾期、补完成到复盘的完整学习历程。
- 通过每日执行、逾期提示和轻量复盘减少拖延。
- 建立从计划、专注、完成、复盘到下一步行动的稳定习惯。

成功状态是：用户打开应用后，可以立刻知道现在应该执行哪一个任务、还剩多少时间、有哪些任务落后，以及自己的学习节奏是否正在变好。

## 产品气质

安静、专注、克制。

应用应该像一个原生 macOS 生产力工具：冷静、精确、响应迅速，并且适合每天反复使用。它可以适配 macOS Liquid Glass 视觉语言，但玻璃质感必须服务于层级、聚焦和系统一致性，不能变成装饰性堆叠。

## 品牌象征

DayDayUp 的产品标志可以是一只生动活泼的小松鼠。

小松鼠代表产品的灵魂：

- 持续积累：松鼠会一点点储存松果，像学习者每天积累知识、项目经验和代码能力。
- 敏捷行动：松鼠反应快、移动轻盈，对应应用希望用户快速进入任务、快速开始学习、快速完成复盘。
- 长期准备：松鼠不是临时努力，而是在为更长周期做准备，对应从小白成长为专业开发者的长期路线。
- 自我驱动：小松鼠不依赖外部监督，强调用户自己规划、自己执行、自己复盘。

视觉上，小松鼠应该聪明、有精神、有行动感，但不能过度幼稚。它可以作为产品标志、空状态插图、完成反馈和轻量提醒角色出现，但不应该变成喧宾夺主的动画吉祥物。

## 反参考

DayDayUp 不应该像：

- 充满徽章、积分、排行榜和社交压力的习惯打卡应用。
- 复杂的项目管理软件，比如带有大量字段、视图和协作功能的任务系统。
- 伪装成应用的营销落地页。
- 忽略 macOS 平台习惯的普通网页看板。
- 过度 AI 风格化的界面，比如大量渐变、发光面板和装饰动画。

## 设计原则

1. 用户自己规划任务，应用只监督执行。
2. 让下一步学习行动一眼可见。
3. 让时间压力可见，但不要制造焦虑。
4. 把进度当成复盘依据，而不是炫耀指标。
5. 优先使用 macOS 原生模式，而不是发明奇怪控件。
6. 复盘必须足够轻量，轻到可以每天坚持。

## 数据指标与评分

应用需要提供一个清晰的数据图，用于表达学习任务的执行质量。推荐使用“学习执行力雷达图”作为核心图表，同时配合一个 100 分制的“执行力评分”。

应用还需要提供任务日历，用于表达每天的执行结果：按时或提前完成任务的日期显示为绿色；没有任务完成、也没有逾期截止任务的日期显示为普通默认颜色；如果某个任务逾期未完成，则该任务的截止日期显示为红色；如果逾期任务后来被补上，则原本红色的截止日期调整为紫色。红色优先级最高，紫色次之，绿色再次之。

学习历程以任务为单位归档。用户可以点开每个任务查看完整闭环：哪一天制定计划，哪一天开始执行，哪一天完成，是否逾期，是否补完成，当前完成度，延期时长，卡住原因，补救记录和复盘备注。没有完成的任务视为未闭环，必须能看到卡在了哪一步。

学习执行力雷达图包含这些维度：

- 任务完成度：已完成任务量占计划任务量的比例。
- 准时完成率：在截止时间前或截止时间当天完成的任务比例。
- 提前完成率：早于截止时间完成的任务比例。
- 延迟控制率：对延迟完成率和平均延迟时长的反向表达，延迟越少分数越高。
- 专注稳定度：计划学习日中实际完成学习时段的比例。
- 复盘完整度：完成任务后有记录备注或复盘的比例。

辅助诊断指标包含：

- 任务闭环率：已经完成并达到完成标准的任务比例。
- 补完成率：逾期后被补上的任务占逾期任务的比例。
- 未闭环任务数：仍未完成或卡住的任务数量。
- 平均延期时长：逾期任务平均晚了多久完成，或已经逾期多久仍未完成。

执行力评分采用 100 分制：

- 任务完成度：30 分。
- 准时完成率：25 分。
- 提前完成率：10 分。
- 延迟控制率：15 分。
- 专注稳定度：15 分。
- 复盘完整度：5 分。

评分不应该只鼓励“快”。提前完成必须建立在任务达到完成标准的前提下，否则不能获得提前完成加分。延迟任务不应该只做简单扣分，还应该展示延迟原因和下一步补救行动。

评分等级建议：

- 90 到 100 分：节奏优秀。
- 75 到 89 分：节奏稳定。
- 60 到 74 分：需要调整。
- 0 到 59 分：执行风险较高。

评分的目的不是制造焦虑，而是帮助用户发现自己是否正在稳定推进，以及拖延主要发生在哪类任务上。

任务完成后的核心反馈文案是：“任务完成啦，开始干饭！”

## 可访问性与包容性

应用应达到 WCAG AA 级别的对比度要求，支持降低动态效果，支持键盘操作，并尊重 macOS 的辅助功能设置，例如增强对比度和降低透明度。数据可视化不能只依赖颜色表达状态。
